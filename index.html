Architecture

How it works under the hood

No proprietary servers or cloud lock-in. Transparent SQLite triggers journal mutations directly inside your local database file.

01 / LOCAL WRITES

Direct SQLite WAL Execution

Mutations hit local SQLite immediately in WAL mode. Your frontend never shows network spinners or waits for server round-trips.

write_latency = < 0.38ms
02 / CDC TRIGGERS

Recursion-Proof Capture

SQLite AFTER INSERT/UPDATE/DELETE triggers capture deltas into _sync_changes. A session-level suppression flag prevents echo loops.

guard: suppressed = 0
03 / CONVERGENCE

Microsecond LWW & Tombstones

Deterministic Last-Write-Wins with microsecond timestamps. Deleted records are tracked in _sync_tombstones so stale packets cannot resurrect them.

rule: deleted_at >= remote_ts
Quickstart

Drop into your Tauri v2 app

Register the plugin in Rust and initialize the TypeScript SDK on the frontend. 

import { SyncManager } from 'tauri-plugin-sync';

// 1. Initialize Sync with your local SQLite database
const sync = await SyncManager.init({
  database: 'app.db',
  endpoint: 'https://api.example.com/sync',
  tables: ['todos', 'notes'],
  authHeader: 'Bearer eyJhbGci...',
  syncIntervalMs: 5000, // background polling interval
  batchSize: 500,       // max changes per batch
});

// 2. Reactive sync status ('idle' | 'syncing' | 'offline' | 'error')
sync.onStatusChange(({ state }) => {
  console.log('Sync status:', state);
});

// 3. Local writes are automatically captured by SQLite triggers
await sync.syncNow();
// src-tauri/src/main.rs
fn main() {
    tauri::Builder::default()
        // Zero-boilerplate plugin initialization
        .plugin(tauri_plugin_sync::init())
        .run(tauri::generate_context!())
        .expect("error running tauri application");
}
